Use `orchestration-bridge:orchestrator-stage` for GitHub issue intake.

Goal: inspect open issues, choose one cohesive evidence-backed work cluster, and prepare the next safe task boundary.

Context: use `gh issue list/view`, repository task truth, related PRs, dependencies, duplicates, blockers, and write ownership.

Verification: labels and delegation add no commands; root final acceptance is one smallest exact set, full suite epic/release-only.

Output: considered issues, chosen cluster/reason, task boundary, routing decision, next action, and blockers.

Stop: blocked access, user-owned product priority, ownership conflict, plugin/settings mutation, PR/merge/deploy, destructive/remote/live action, or scope expansion.
