# Agent Harness

**Готовая рабочая среда для разработки с Codex и Claude Code.**

Harness — это набор инструкций, навыков и инструментов, который помогает
агенту вести задачу от запроса до проверенного результата. Вы описываете, что
нужно сделать, а агент получает общий порядок работы: разобраться в проекте,
внести изменения, проверить их и оставить понятное описание результата.

Главная польза — меньше повторять одни и те же правила в каждом разговоре,
проще продолжать работу после перерыва и пользоваться двумя агентами в одном
проекте. Например, Codex может реализовать изменение, а Claude — независимо
проверить его, опираясь на те же проектные инструкции.

## Что входит и зачем

| Компонент | Чем помогает |
| --- | --- |
| Общие инструкции | Задают правила работы с вашим кодом, чужими изменениями и проверками |
| Навыки — инструкции для отдельных видов задач | Помогают настроить проект, спланировать сложную работу, найти ошибку или завершить задачу |
| Специализированные помощники | Дают агенту роли для разработки, проверки кода, документации и других задач |
| Локальная веб-консоль | Собирает готовые команды-запросы, сведения об агентах и состоянии рабочего окружения |
| Beads | Хранит задачи и их состояние в проекте, чтобы работа не зависела только от истории чата |
| Context | Даёт инструмент поиска документации по используемым библиотекам |
| Установщик | Устанавливает комплект для обоих агентов, проверяет его и ведёт журнал для отката |

Вы продолжаете работать в обычных Codex и Claude Code. Harness размещает
инструкции и навыки там, где их читают клиенты. Для каждого проекта добавляются
его собственные правила. Консоль запускается на вашем компьютере; держать её
открытой для работы агента не обязательно.

Для установки достаточно этого открытого репозитория. Используются ваши
аккаунты Codex и Claude и их обычные лимиты. Установка сама не запускает задачи
у моделей; запросы агентов обрабатываются выбранными вами провайдерами.
Harness помогает организовать работу, но результат кода по-прежнему нужно
проверять. Дополнительные подключения — граф кода Graphify, каталог внешних
навыков и синхронизация задач с GitHub — для начала не нужны.

## Перед началом

Версия: **0.2.0-rc.3**, ранний выпуск для пользователей.

- **Linux и Windows с WSL:** основной путь; установка и консоль проверены в Linux/WSL.
- **macOS:** установка допускается, но весь путь на Mac пока не проверен.
- **Windows без WSL:** этот установщик не поддерживается.

Ниже описан запуск через терминал для **обоих** клиентов. Если вы пользуетесь
только приложением Codex, установите также Codex CLI — его терминальную версию.
В WSL все команды, включая `codex` и `claude`, должны выполняться внутри Linux.
Настройки установленных в Windows приложений автоматически не переносятся.

Команды выполняйте по порядку. Если шаг закончился ошибкой, сначала исправьте
её. `~` в путях означает вашу домашнюю папку. Сам harness устанавливайте без `sudo`.

## Шаг 1. Подготовить терминал и базовые инструменты

### Если у вас Windows

Если WSL уже установлен, откройте Ubuntu и переходите к следующему подразделу.
Иначе откройте PowerShell **от имени администратора** и выполните:

```powershell
wsl --install
```

Перезагрузите компьютер, откройте Ubuntu и создайте пользователя по подсказкам.
Все дальнейшие команды выполняйте в терминале Ubuntu.
[Инструкция Microsoft по WSL](https://learn.microsoft.com/en-us/windows/wsl/install).

### Linux / Ubuntu в WSL

Нужны Git, curl и Python 3.11 или новее. В Ubuntu их можно установить так:

```bash
sudo apt update
sudo apt install git curl python3
python3 --version
```

Если версия Python ниже 3.11, обновите окружение; например, используйте Ubuntu
24.04 или новее. Для других Linux-дистрибутивов установите эти же инструменты
через их менеджер пакетов.

### macOS

Установите [Git](https://git-scm.com/downloads/mac) и
[Python 3.11+](https://www.python.org/downloads/macos/), затем откройте Terminal.
Остальные команды ниже общие для Linux и macOS. Ограничение по проверке Mac
сохраняется — это пока экспериментальный путь.

### Node.js и npm

Если `node --version` уже показывает **24.x**, а `npm --version` работает,
переходите дальше. Иначе установите Node.js 24 через
[nvm](https://github.com/nvm-sh/nvm#installing-and-updating) — менеджер версий Node:

```bash
curl -fsSL https://raw.githubusercontent.com/nvm-sh/nvm/v0.40.7/install.sh | bash
```

Закройте и снова откройте терминал, затем выполните:

```bash
nvm install 24
nvm use 24
node --version
npm --version
```

Node нужен для сборки консоли; npm устанавливается вместе с ним.
Другие версии можно проверить командой `harness plan` после получения комплекта:
требование текущей сборки — `^20.19.0 || >=22.12.0`.
[Другие способы установки Node.js](https://nodejs.org/en/download).

## Шаг 2. Установить Codex, Claude и вспомогательные инструменты

Уже установленные инструменты повторно устанавливать не нужно.
Команды ниже скачивают установщики из указанных официальных источников.

**uv — для Python-зависимостей консоли:**

```bash
curl -LsSf https://astral.sh/uv/install.sh | sh
```

[Документация uv](https://docs.astral.sh/uv/getting-started/installation/).

**Codex CLI:**

```bash
curl -fsSL https://chatgpt.com/codex/install.sh | sh
```

[Установка Codex](https://developers.openai.com/codex/cli).

**Claude Code CLI:**

```bash
curl -fsSL https://claude.ai/install.sh | bash
```

[Установка Claude Code](https://code.claude.com/docs/en/setup).

**Beads и Context — учёт задач и поиск документации:**

```bash
npm install -g @beads/bd @neuledge/context
```

[Beads](https://github.com/gastownhall/beads#-installation) ·
[Context](https://github.com/neuledge/context#-quick-start).

Откройте новый терминал. Добавьте каталог пользовательских команд, если он ещё
не доступен в текущем терминале:

```bash
export PATH="$HOME/.local/bin:$PATH"
```

Чтобы эта настройка сохранялась, добавьте ту же строку один раз в `~/.bashrc`
для Bash или в `~/.zshrc` для Zsh. Затем проверьте:

```bash
git --version
python3 --version
node --version
npm --version
uv --version
codex --version
claude --version
bd --version
context --help
```

Каждая команда должна выполниться без `command not found`. Затем по очереди
запустите `codex` и `claude`, войдите в свои аккаунты по подсказкам клиентов и
закройте их. Теперь инструменты готовы к установке harness.

## Шаг 3. Скачать harness

Используйте новую папку. Эта команда получает конкретную версию:

```bash
git clone --branch v0.2.0-rc.3 --depth 1 https://github.com/maslennikov-ig/agent-harness.git ~/agent-harness
cd ~/agent-harness
```

Если `~/agent-harness` уже существует, не удаляйте её: выберите другое свободное
имя и используйте его дальше. Сохраняйте папку комплекта на месте — установленные
команды ссылаются на неё. В WSL храните её в домашней папке Linux.

## Шаг 4. Посмотреть план и установить

Сначала посмотрите, какие каталоги затронет установка:

```bash
./bin/harness plan
```

План проверяет обязательные инструменты, целостность комплекта и конфликты.
Для списка каждого файла выполните `./bin/harness plan --verbose`.
Если ошибок нет, установите:

```bash
./bin/harness bootstrap
./bin/harness doctor
```

Первая команда собирает консоль и размещает инструкции, навыки и помощников
для обоих клиентов. При первом запуске нужен интернет для загрузки зависимостей.
Вторая проверяет состав и содержимое установленных файлов.

Успешный результат заканчивается сообщением:

```text
doctor: release 0.2.0-rc.3 and installed paths are exact
```

Установка выводит путь к журналу восстановления. По умолчанию это
`~/.agent-harness/state/install-journal.json`. Повторный `bootstrap` той же
версии не должен создавать дубли.

Если найдены ваши инструкции, навыки или помощники с совпадающими именами,
установщик может остановиться. Он также останавливается, если личный
`~/.codex/AGENTS.md` ещё не содержит управляемого блока harness. Сохраните этот
файл и согласуйте правила вручную — не удаляйте свои настройки ради продолжения.
Текст вне уже существующих управляемых блоков сохраняется.

## Шаг 5. Подключить проект

Для знакомства удобно создать небольшой отдельный проект:

```bash
mkdir ~/harness-playground
cd ~/harness-playground
git init
harness init-project "$PWD"
```

Команда создаёт три файла:

| Файл | Назначение |
| --- | --- |
| `AGENTS.md` | Общие правила работы агентов в этом проекте |
| `CLAUDE.md` | Подключение этих правил для Claude |
| `.codex/orchestrator.toml` | Начальные настройки рабочего процесса |

Это основа проекта. Когда понадобится настроить команды сборки, проверок и
работу с задачами под реальный репозиторий, попросите агента применить навык
`orchestration-setup`. Он должен учитывать устройство вашего проекта.

Для существующего проекта перейдите в его папку и выполните
`harness init-project "$PWD"`. Если там уже есть инструкции, команда сообщит
конфликт до записи. Сначала сохраните изменения в Git или резервной копии,
затем согласуйте новые правила с существующими. Подключать проект после каждой
задачи заново не нужно.

## Шаг 6. Работать с агентами

Из папки проекта запустите Codex:

```bash
codex
```

Опишите задачу обычными словами. Например: «Сделай небольшую функцию обработки
текста, добавь проверки для обычного и пустого ввода и объясни, как её запустить».
В новой сессии должны быть доступны установленные навыки и помощники.

Чтобы продолжить с Claude, завершите текущую работу и выполните в той же папке:

```bash
harness claude
```

**Для Claude используйте `harness claude`.** Эта команда подключает два набора
навыков и помощников: `orchestration-bridge` и Superpowers. Обычная команда
`claude` сама эти наборы не подключает. Навыки Claude имеют имена
`/orchestration-bridge:…` и `/superpowers:…`.

Можно поручить Claude проверить сделанные изменения или выполнить следующую
задачу. Смена агента не переносит историю чата автоматически: перед продолжением
попросите первого агента записать результат и оставшиеся шаги в проект.
Не запускайте одновременное редактирование одного файла двумя агентами.

## Шаг 7. Открыть консоль

```bash
orch-prompts open
```

Команда запускает локальную веб-консоль и открывает её адрес. Здесь можно найти
готовые запросы для типовых задач и посмотреть сведения о рабочем окружении.
Если браузер не открылся, скопируйте выведенный URL в браузер вручную.
В WSL открывайте его в **Windows-браузере**.

Консоль показывает установленный состав. Это не подтверждение того, что
конкретная сессия агента уже загрузила все навыки: проверяйте их в новой сессии.

## Обновление и удаление изменений harness

Автоматическое обновление harness не включается. `harness update` применяет
версию из вашей локальной папки, но не скачивает её. При появлении нового релиза
следуйте его инструкции и используйте указанный тег; не меняйте версию посреди
незавершённой задачи без необходимости.

Для отката:

```bash
harness rollback
```

Откат возвращает управляемые файлы к состоянию **до первой установки**, включая
файлы подключённых через установщик проектов. Это не переключение на предыдущую
версию harness. Журнал сохраняет исходное состояние и после обновлений.

До отката сохраняйте папку комплекта и подключённые проекты на месте. Если вы
изменили или удалили управляемый файл, откат остановится: сначала сохраните свои
изменения и согласуйте их с записанным состоянием. Не удаляйте целиком каталоги
`~/.codex`, `~/.claude` или `~/.agents` — там могут быть другие ваши настройки.

После прерванной установки или отката повторите `harness rollback`. Если он
успешно завершился, можно установить комплект заново. Редкое ограничение ранней
версии: принудительное завершение процесса на последнем шаге очистки может
оставить пустые каталоги, которые потребуется разобрать вручную.

## Если что-то не получилось

| Симптом | Что сделать |
| --- | --- |
| `command not found` | Проверьте шаг 2, откройте новый терминал и проверьте PATH |
| `required command is missing` | Установите названный инструмент, затем повторите `plan` |
| Неподходящая версия Python или Node | Проверьте версии из шага 1; не запускайте установку с ошибкой |
| Конфликт инструкций, навыка или помощника | Сохраните свой файл и согласуйте его с harness; не используйте принудительную перезапись |
| `doctor` сообщает изменения | Прочитайте указанные пути; сохраните свои правки перед восстановлением |
| Claude не видит навыки harness | Запустите новую сессию через `harness claude` |
| Консоль не открылась | Выполните `orch-prompts status` и откройте её URL вручную |

Если нужна помощь, создайте [обращение в репозитории](https://github.com/maslennikov-ig/agent-harness/issues)
с командой, текстом ошибки, версией harness, ОС и версиями обоих клиентов.
Не прикладывайте ключи, файлы авторизации или содержимое закрытых проектов.

## Что проверено в этой версии

В публичный комплект входят 26 автоматических тестов: 25 сценариев установщика
и один сценарий состава консоли. Они проверяют целостность, конфликты,
повторную установку, оба Claude-плагина, откат и сохранность пользовательских
инструкций. Реальные задачи с пользовательскими аккаунтами и полный путь на
macOS здесь не заявлены как проверенные.
